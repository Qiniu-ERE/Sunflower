# 现场演示脚本（总共 10 分钟：实操约 5 分钟 + 答疑约 5 分钟）

彩排 / 演示前：`python3 -m sunflower.demo reset`（工作区回到预埋 bug 的初始状态，Codex 开新会话）。**不跑这步，第 1 步就看不到红色失败、第 4 步会播「删除命令已存在」**（10-24 彩排踩过）。

开讲前另开一个终端跑 `python3 -m sunflower.demo preview` 并一直开着：工作区每次提交后它停掉旧网页服务、按当前代码重启 `todo.py serve`，任务一完成，面板上 Codex 给的 `127.0.0.1:8000` 就能直接点开；撤销 / 重置后代码里没有网页入口，服务跟着停。不要让 Codex 自己「运行服务」：serve 不退出，任务结束不了。

## 说话要点

- 面板窗口放在前台：按空格（或翻页笔、或点右上角按钮）→ 按钮变红「录音中」再开口 → 说完停半秒再按。本机直接打开 `http://127.0.0.1:8787/panel`，不用令牌；按键由面板经主机转给桌面设备（常驻或终端里开着的都行）。
- 用中文说功能（"删除命令""完成的事项"），少说英文文件名 / 函数名——平台 ASR 会听错。
- 说完马上按停：录音开着会把旁边人的话一起识别，原样派给 Codex 并显示在屏幕上（10-24 彩排一段 10 秒的录音混进了旁人半句话）。
- 一句话一个需求。疑问句（"有没有问题"）也会派给 Codex，只读不改。

## 兜底

- 面板按键没反应（按钮提示「设备没在线 / 没响应」）：终端跑 `python3 -m sunflower.service status` 看「设备」一行；常驻设备没起来就 `service device-uninstall` 后在终端 `service device`，终端里按空格同样能说。
- 现场网络挂：播放 PPT 里的全流程录屏。
- 执行流停在「会话已建立」超过 60 s 没有新的一步：上游渠道挂住了（icodeeasy 生产 17 次里 1 次），说「停下」再把那句话说一遍。响应流出后中途断的情况 Codex 会在 60 s 内自己断开重试（#47）；请求发出后迟迟没有响应的情况没有超时可设，只能这样手动处理。
- 第 4 步超过 90 s 还没播报：说「进度怎么样了」后直接转答疑，结果播报会在答疑中途到。
- Codex 慢（qiniu-gpt 流式断连重连）：第 4 步可换成更小的需求，如"把列表里已完成的事项标成绿色"。
